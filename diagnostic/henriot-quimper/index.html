Ce que j'ai relevé

Aucune balise viewport : le site n'a pas de version mobile

Le code de la page d'accueil ne contient aucune balise viewport. Conséquence concrète : sur un téléphone, le navigateur affiche la version bureau réduite en miniature. Le visiteur doit zoomer et faire glisser la page pour lire. C'est le point qui coûte le plus de visiteurs aujourd'hui, la majorité des consultations se faisant sur mobile.

Corrigé dans la maquette : la maquette s'adapte à la largeur de l'écran, le texte reste lisible sans zoom.

Aucun lien d'appel direct

Le numéro de la manufacture apparaît en texte, mais aucun lien tel: n'existe sur la page. Depuis un téléphone, il faut le retenir ou le recopier pour appeler.

Corrigé dans la maquette : le numéro devient un bouton d'appel en un geste, présent en haut de page et en bas.

94 requêtes réseau pour afficher la page d'accueil

Chaque élément — image, script, feuille de style — déclenche un aller-retour avec le serveur. 94 pour une page d'accueil est beaucoup, et c'est ce qui pénalise le plus l'affichage sur une connexion mobile.

Corrigé dans la maquette : la maquette charge une seule page autonome, sans dépendance externe.

Chargement mesuré dans un navigateur mobile simulé : 2,18 s, 94 requêtes réseau, 250 Ko transférés. Balises de la page d'accueil lues directement dans le code source.
