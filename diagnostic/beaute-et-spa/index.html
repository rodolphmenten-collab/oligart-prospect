Plus la note est haute, plus le site a de marge de progrès. Elle est calculée sur cinq critères : affichage mobile, vitesse, design, conversion et bases techniques.

Ce que j'ai relevé

1,17 Mo à charger pour la seule page d'accueil

Sur une connexion mobile ordinaire, cela représente plusieurs secondes d'attente avant que la page s'affiche. Six des neuf images sont servies dans une définition au moins deux fois supérieure à leur taille d'affichage : le téléphone télécharge des images qu'il réduit ensuite.

Corrigé dans la maquette : des images à la bonne dimension et une page allégée, qui s'affiche en moins d'une seconde.

Le zoom est bloqué sur mobile

La balise viewport contient maximum-scale=1.0, ce qui empêche d'agrandir la page avec deux doigts. Pour une clientèle qui n'a pas toujours une vue de vingt ans, c'est un obstacle réel — et c'est aussi un critère d'accessibilité.

Corrigé dans la maquette : le zoom est rendu, et les tailles de texte sont revues pour qu'on n'en ait pas besoin.

Deux systèmes de réservation différents cohabitent

La page renvoie vers deux outils de réservation distincts. Le visiteur qui veut réserver doit deviner lequel correspond à ce qu'il cherche. Chaque hésitation dans un parcours de réservation coûte des rendez-vous.

Corrigé dans la maquette : un seul bouton « Réserver », un seul parcours, pour les soins comme pour le studio.

Comment j'ai mesuré

Chargement mesuré dans un navigateur mobile simulé : 1,17 Mo transférés sur la page d'accueil, 49 requêtes. Balises et dimensions d'images lues dans le code source.

Relevé effectué le 25 septembre 2026 sur la page d'accueil. Les chiffres proviennent de mesures réelles de chargement dans un navigateur, pas d'une estimation.
